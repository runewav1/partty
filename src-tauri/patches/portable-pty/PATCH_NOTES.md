# portable-pty (patched)

Upstream: https://github.com/wezterm/wezterm/tree/main/pty
Base commit: f8921727a11b9f8b073e8c24821d72fd41283500

## Patch

Commit `45d9b48`: Enables `PSEUDOCONSOLE_PASSTHROUGH_MODE` in
`CreatePseudoConsole` flags so ConPTY passes unrecognized escape
sequences (DCS, APC) through to xterm.js instead of silently dropping
them. Required for Sixel and Kitty graphics protocols.

Commit `fd5085b`: Modernization pass replaces the legacy Windows dependency stack with `windows-sys`:

- dynamic `conpty.dll` loading via `shared_library` replaced with
  `LoadLibraryW`/`GetProcAddress` behind a `OnceLock`
- the `winreg` registry environment reader replaced with raw `Reg*`
  API calls (`SZ`/`EXPAND_SZ`/`MULTI_SZ` semantics preserved)
- all `winapi` types replaced with `windows-sys` equivalents

Commit `ced5596`: Documentation-only wording/formatting fix in this file.

Commit `a3d401b`: Fixes an inverted success check in `TerminateProcess`.
`TerminateProcess` returns non-zero on success, so the upstream
`if res != 0` logic reported failure on successful kills and success
on failures (`WinChild::do_kill` and `WinChildKiller::kill`).

Commit `317e860`: Adds `.gitignore` for the vendored copy (`target/`,
`Cargo.lock`).

Commit `55e8d62`: Resolves all `cargo clippy` warnings and applies
`cargo fmt`:

- `clippy::uninit_vec` (deny-by-default, was a hard error): the
  proc-thread-attribute-list buffer is now zero-initialized
  (`vec![0u8; ..]`) instead of `Vec::with_capacity` + `unsafe set_len`
- `clippy::manual_map`, `clone_on_copy`, `redundant_field_names`,
  `useless_conversion`, `needless_borrows_for_generic_args`,
  `chunks_exact_to_as_chunks`, `unnecessary_cast`: cosmetic cleanups,
  no behavior change
- `clippy::upper_case_acronyms`: `HPCON` deliberately mirrors the
  Windows SDK typedef; suppressed with `#[allow]` rather than renamed
- `clippy::const_is_empty` in the `narrow`/`whoami` examples:
  suppressed — the dead `to_write` branch is intentional demo
  scaffolding
- also drops one preliminary `as _` cast in `src/lib.rs`

Commit `c88d395`: Removes the remaining `as _` casts in the Windows
layer (`src/win/mod.rs`, `src/win/psuedocon.rs`) so `RawHandle` values
flow through the `windows-sys` signatures directly instead of relying
on cast-driven type inference.

## Updating to a new upstream version

```sh
cd patches/portable-pty

# Find the new upstream commit for the desired portable-pty release.
# Use `cargo info portable-pty` or check the WezTerm changelog.

# Fetch the upstream wezterm monorepo.
git fetch upstream

# Checkout your desired upstream base (e.g. a specific commit or tag):
git checkout <new-upstream-commit>

# The portable-pty crate lives at path `pty/` in the wezterm repo.
# Extract it:
git checkout <new-upstream-commit> -- pty/

# Move the pty/ contents to repo root, then:
git add -A
git commit -m "portable-pty X.Y.Z (upstream base)"

# Re-apply our patches in order. Cherry-pick the ones that apply cleanly:
git cherry-pick 45d9b48     # PSEUDOCONSOLE_PASSTHROUGH_MODE

# The windows-sys modernization (fd5085b) is a dependency-stack
# refactor, not cherry-pickable — diff it from the previous base and
# re-apply by hand, e.g. `git diff 45d9b48 fd5085b`, then commit.

# The follow-up fixes depend on the modernization. Re-apply them in
# order; they may need manual resolution against the new base:
git cherry-pick a3d401b     # TerminateProcess success check
git cherry-pick 55e8d62     # clippy warnings + cargo fmt
git cherry-pick c88d395     # drop remaining `as _` casts

# ced5596 (docs) and 317e860 (.gitignore) can be re-applied as-is or
# regenerated by hand.

# NOTE: 55e8d62 also runs `cargo fmt` across the whole crate, which can
# conflict heavily on a new base. If it does, keep the meaningful fixes
# (especially the `uninit_vec` fix in src/win/procthreadattr.rs) and
# drop the purely cosmetic formatting hunks.

cargo build   # verify
```
